# Domain documentation

udpstp has one domain glossary, [GLOSSARY.md](../../GLOSSARY.md), and one directory of [architecture decisions](../adr/).

Read the glossary before naming protocol concepts in code, tests, events, command-line output or documentation. Use its canonical terms and respect its _Avoid_ lists. Propose a missing definition rather than inventing a synonym.

The glossary defines domain terms. Implementation details, plans and design decisions belong in their own documents.

Read the ADRs that touch a change before implementing it. Surface a conflict with a settled decision and explain the tradeoff before changing that decision.
