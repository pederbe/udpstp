# Issue tracker

Before any public write or edit, follow the [public content and editing rules](../../CONTRIBUTING.md#public-issues-and-pull-requests). Use only the template's sections and keep working notes in private records.

Use the repository's [GitHub Issues](https://github.com/pederbe/udpstp/issues) for bugs, interoperability reports, questions and feature proposals. Search existing issues before opening another report. The web interface and GitHub CLI are both suitable.

For a bug, include the udpstp version, operating system, command and relevant configuration, expected behavior and observed result. Remove Shared Keys and other private data from logs. For interoperability reports, include the peer implementation and version.

Discuss substantial changes before implementing them. Link related public issues from a pull request and explain its behavior and validation. [CONTRIBUTING.md](../../CONTRIBUTING.md) describes the contribution conventions.

Report vulnerabilities through [private vulnerability reporting](https://github.com/pederbe/udpstp/security/advisories/new), following [SECURITY.md](../../SECURITY.md).

The [triage label guide](triage-labels.md) explains issue states. A label describes readiness or the information needed. Check the discussion and assignment before starting work.
